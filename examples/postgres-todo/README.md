# PostgreSQL example: todo API with SQLAlchemy and Alembic

An async CRUD API backed by PostgreSQL, with schema migrations. The same code runs on SQLite:
only `DATABASE_URL` changes.

```bash
pip install -r requirements.txt     # runapi[postgres]
cp .env.example .env                # set SECRET_KEY
docker compose up -d db             # PostgreSQL 16 on localhost:5432
runapi db upgrade                   # apply migrations/ (creates the todos table)
runapi dev
```

No Docker? Use SQLite instead: `pip install "runapi[sqlite]"` and set
`DATABASE_URL=sqlite+aiosqlite:///./app.db` in `.env`.

```bash
curl -X POST localhost:8000/todos -H 'content-type: application/json' -d '{"title": "ship it"}'
curl localhost:8000/todos
curl -X PUT localhost:8000/todos/1 -H 'content-type: application/json' -d '{"done": true}'
curl localhost:8000/ready           # {"status":"ready","checks":{"database":true}}
```

## How it fits together

| File | Role |
|------|------|
| `db.py` | `database = Database()` reads `DATABASE_URL` |
| `main.py` | `runapi_app.use_database(database)`: connect on startup, dispose on shutdown, adds a `/ready` check |
| `models/todo.py` | SQLAlchemy model on `runapi.Base` |
| `routes/todos/*.py` | handlers get a session with `Depends(database.get_session)`; it commits when the request finishes and rolls back on errors |
| `migrations/` | Alembic (async). `env.py` reads `DATABASE_URL` and `Base.metadata` |

## Changing the model

```bash
# edit models/todo.py, then:
runapi db migrate -m "add due date"   # autogenerate a migration, review it!
runapi db upgrade
runapi db downgrade                   # undo one step
```

Autogenerated migrations should always be reviewed. Generate them against the database you deploy
to (PostgreSQL), since SQLite renders some defaults differently.
